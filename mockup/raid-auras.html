Healer Forever: buffs and debuffs in the raid view (future feature)

One sample bar per scenario, zoomed so every pixel is readable, for the current party bar and the four raid styles from the raid frames mockup. You play a Paladin (Cleanse: Magic, Poison, Disease). Back to the main mockup · Chosen: style D with my buffs and dispels

Buffs in raid

  • By default only your buff matters: gold marker = your blessing is missing, orange marker = it is ending (under 60 s or 5 %, the same rebuff rule as the party buff button).
  • Full buff icon rows are off in raid: 40 bars × 6 to 10 icons each is unreadable at 22 to 28 px.
  • Other classes' buffs (Fortitude, Mark of the Wild, Arcane Intellect) can show as tiny optional pips in the bottom-left corner: white Priest, orange Druid, light blue Mage. Information only (you can't cast them), handy for raid leaders, and can be turned off. This page starts with pips on so you can see them; the addon default would be "Missing + ending".

Debuffs in raid

  • By default only debuffs you can dispel, at most 2, dispellable-by-you first.
  • Option to also show Curses (other classes dispel them) or everything, including physical debuffs like Mortal Strike. Those are drawn dimmer so they never look like your job.
  • Full names, stacks and time are always in the hover tooltip (all debuffs, like the party tooltip).

Combat limits on WoW Forever

  • Aura data can be hidden from addons in combat.
  • Debuff icons drawn by the game's own aura container keep working in combat (that is how party debuffs work now).
  • Missing-buff markers update out of combat only: like the party buff button, they hide in combat and are re-checked when combat ends.
  • Colouring the bar edge or a corner square by debuff type needs the type in our code: needs checking in game.
  • Each marker below has a badge: works in combatout of combat onlyneeds checking in game

Options > Raid Layout > Buffs and debuffs

These controls map 1:1 to future raid-layout options (saved separately from the party settings). They change the four raid columns live. The party column always shows the current party look and is not affected.

How it would be built, and the WoW API limits

  • Debuff icons (A, D, party): CreateFrame("AuraContainer", nil, bar, "CustomAuraContainerTemplate") with SetUnit(unit) and one AddAuraGroup per priority: first "HARMFUL|RAID_PLAYER_DISPELLABLE" (dispellable by me), then "HARMFUL" for the dimmed rest when the option asks for it. The game draws, sorts and updates them in combat, with the dispel-type border from Enum.CustomAuraButtonDispelTypeTextureStyle (the same path the party bars use today). Check in game: whether two groups on one container show a Magic debuff twice, and whether the second group can be desaturated (Icon:SetDesaturated(true) in the button template) or only dimmed with SetAlpha. "Any dispellable" (Curse but not physical) has no game filter I know of: that mode needs our own type check, so it is "needs checking".
  • Type-coloured edge (B) and corner squares (C): four 2 px Interface\Buttons\WHITE8X8 strips or a 6 px WHITE8X8 square, tinted by type. In combat the type may be secret; a colour curve (C_CurveUtil.CreateColorCurve keyed on Enum.SpellDispelType, like the party icon border) could tint it without reading it, if the game hands us a curve-ready value for raid units. Unverified, so "needs checking". Fallback: one game-drawn icon.
  • My missing/ending blessing: computed from the aura list out of combat only (PLAYER_REGEN_ENABLED, UNIT_AURA while out of combat), exactly like the party buff button. In combat the marker hides. Gold dot: Interface\COMMON\Indicator-Yellow (from memory) or a tinted WHITE8X8 circle mask; small icon: the blessing's spell icon from C_Spell.GetSpellTexture with a 1 px tinted WHITE8X8 border.
  • Other classes' pips: three 4 px WHITE8X8 textures (vertex colour = class colour from RAID_CLASS_COLORS), same out-of-combat check. Only buffs that somebody in the raid can actually cast are checked (no Druid in the raid = no orange pip), and Arcane Intellect only for mana users.
  • Dead / ghost / offline: all buff and debuff markers hide (UnitIsDeadOrGhost). Out of range: the whole frame dims (SetAlphaFromBoolean from UnitInRange), so the markers dim with it; there is no line of sight check for friendly units.
  • All markers are pre-created per button and only shown or hidden, so nothing is created in combat. Updates are event-driven (UNIT_AURA with updateInfo), never polled.
