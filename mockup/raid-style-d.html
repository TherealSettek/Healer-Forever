Healer Forever: raid style D "Hurt stands out", with my buffs and my dispels

Focused follow-up to raid frames and raid buffs and debuffs: only style D, with the buff and debuff rules you chose. Pick another class with "You play" in the panel. Hover a bar or a buff icon for its tooltip. Back to the main mockup

Decided

  • Raid style D, "Hurt stands out" (64 × 24): bars at full health are a muted dark class tint; hurt bars are full class colour with a red deficit (−1.8k).
  • Works for every class, not only Paladins: buffs and dispels follow the class you play.
  • Buffs: only MY buffs (the buffs in my preset from my class catalog: Paladin blessings, Priest Fortitude, Druid Mark of the Wild, Mage Arcane Intellect). No pips or markers for other people's or other classes' buffs. Missing = small spell icon of the missing buff with a thin gold border, top-right. Several missing = first icon plus a count badge ("2").
  • Ending = less than 5 % of the buff's total duration left (the same rebuff % rule the addon uses): same icon with an orange border plus a pulse (decided: "Orange border + pulse"). The time left is in the hover tooltip.
  • Debuffs: only the ones your class can dispel (Paladin: Magic, Poison, Disease; Priest: Magic, Disease; Druid: Curse, Poison; Shaman: Poison, Disease; Mage: Curse). Everything else, including physical debuffs, is hidden on the bar (still listed in the bar tooltip as "hidden: not dispellable by your class"). Max 3 (option 1–3), in dispel-type order. Decided look: (e) "Glow + icons": the whole bar edge glows in the type colour of the first dispellable debuff, plus the small game-drawn debuff icons bottom-right (up to 3; they shrink to fit on narrow bars).
  • Several of my buffs (open, pick in section 2): default "One icon per state" = the first missing buff with a count badge, plus the first ending buff (orange pulse). Also offered: first icon + count only, or a stack of up to 3 icons.
  • Combat: debuff icons are drawn by the game's own aura container, so they work in combat (letters and glow need checking in game). My-buff markers are worked out out of combat only and hide in combat (like the party rebuff button), then are re-checked when combat ends. Option: "Keep last known (dimmed)" instead.
Party layout unchanged, previous settings preserved. This is the separate Raid layout with its own saved settings. How it would be built in WoW, and the API limits

  • Bar: Interface\TargetingFrame\UI-StatusBar on a StatusBar, 1 px border from Interface\Buttons\WHITE8X8. Muting = GetStatusBarTexture():SetVertexColor() from a colour curve on UnitHealthPercent; deficit = UnitHealthMissing (both newer API, from memory, unverified on Forever; fallback: normal colours, no deficit). Names/health can be secret, so the name is cut with FontString:SetWidth, not string.sub.
  • My-buff icon: a pre-created 10 px Texture per button, texture from C_Spell.GetSpellTexture(spellID) (no hard-coded path), cropped with SetTexCoord(.07,.93,.07,.93), inside a 1 px WHITE8X8 border tinted gold (1, 0.82, 0) or orange (1, 0.54, 0.1). For reference the icons are, from memory: Wisdom Interface\Icons\Spell_Holy_SealOfWisdom, Might Interface\Icons\Spell_Holy_FistOfJustice, Kings Interface\Icons\Spell_Magic_MageArmor, Salvation Interface\Icons\Spell_Holy_SealOfSalvation. Count badge: NumberFontNormalSmall FontString on a black WHITE8X8 backing.
  • Clock sweep: CreateFrame("Cooldown", nil, icon, "CooldownFrameTemplate"), SetCooldown(expiration − window, window) where window = duration × rebuff % (so it sweeps once across the ending window), SetHideCountdownNumbers(true), SetDrawEdge(false). The game animates it, no OnUpdate. Pulse: an AnimationGroup with one Alpha animation, SetLooping("BOUNCE").
  • Hover on the buff icon: the icon frame gets SetMouseMotionEnabled(true) and SetMouseClickEnabled(false) so clicks still reach the secure click-cast button underneath (from memory: check in game that clicks pass through). Its tooltip is our own text (a missing buff has no aura to show).
  • Buff state is read from the aura list out of combat only (UNIT_AURA while out of combat, plus a full re-check on PLAYER_REGEN_ENABLED), exactly like the party buff button. In combat aura data can be secret on WoW Forever, so by default the icons hide on PLAYER_REGEN_DISABLED. "Keep last known (dimmed)" leaves them with SetAlpha(0.45) + SetDesaturated(true); the sweep keeps running from the last known expiry, but a rebuff or dispel by someone else in combat won't be seen until combat ends.
  • Debuff icons: CreateFrame("AuraContainer", nil, bar, "CustomAuraContainerTemplate"), SetUnit(unit), one aura group with filter "HARMFUL|RAID_PLAYER_DISPELLABLE" (dispellable by me), max 1–2. The game draws, sorts and updates them in combat, with the dispel-type border (Enum.CustomAuraButtonDispelTypeTextureStyle, colours from DebuffTypeColor: Magic blue, Poison green, Disease brown). Curses and physical debuffs never enter that filter, so they are hidden with no code of ours.
  • Text layout: name = GameFontNormalSmall-based FontString at the "Name size" (7 px default), SetPoint("TOPLEFT", 2, -1), grey vertex colour, SetWordWrap(false). Missing HP = a bold outlined FontString (NumberFontNormalLarge-style, about half the bar height), anchored CENTER of the free area (left of the right-side icons, below the name). On short bars the number is anchored centre-right and the name gets SetPoint("TOPRIGHT", number, "TOPLEFT", -3, 0), so the name is cut and the number never shrinks. Dead/ghost/offline use the same centre FontString.
  • Debuff display and combat (honest version): on WoW Forever the debuff type can be hidden from addon code in combat. Icons work in combat because the game's aura container draws the type-coloured border itself (AddDispelTypeTexture on the aura button, from memory). Letters and the whole-bar glow need the type in our code, or a trick: hand the container a bar-sized glow texture through AddDispelTypeTexture (anchored to the whole bar instead of the icon) so the game tints it. Unverified, so (b), (c) and (d) are marked "needs checking in game"; (a) "works in combat". Fallback if the check fails: icons.
  • Which debuffs: the filter "HARMFUL|RAID_PLAYER_DISPELLABLE" already means "what my class can dispel" (the game decides per class, no list in our code). "All dispellable types" has no game filter I know of, so it needs our own type check: needs checking in game. Dispel spells (from memory): Paladin Cleanse/Purify, Priest Dispel Magic + Cure/Abolish Disease, Druid Remove Curse + Cure/Abolish Poison, Shaman Cure Poison + Cure Disease, Mage Remove Lesser Curse.
  • Other classes' buff icons (from memory): Power Word: Fortitude Interface\Icons\Spell_Holy_WordFortitude, Divine Spirit Interface\Icons\Spell_Holy_DivineSpirit, Mark of the Wild Interface\Icons\Spell_Nature_Regeneration, Thorns Interface\Icons\Spell_Nature_Thorns, Arcane Intellect Interface\Icons\Spell_Holy_MagicalSentry. In the addon they come from C_Spell.GetSpellTexture.
  • Range: UnitInRange (about 40 yd, can be secret) dims the whole frame with SetAlphaFromBoolean; markers dim with it. No line of sight check exists for friendly units, and other units' facing isn't available. Not visible (UnitIsVisible false): no aura data, so no markers, "?" health. Dead/ghost/offline: all markers hidden.
  • Raid frames come from a SecureGroupHeaderTemplate; size, spacing and arrangement can't change in combat (applied on PLAYER_REGEN_ENABLED). Preview frames are plain non-secure Frames with fake data, never unit tokens.
