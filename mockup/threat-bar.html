Healer Forever threat bar (party frames)

A new threat strip above each party member's health bar (the power bar stays below). Built on the approved look: the original bars with a tooltip-style border around the health and power bars, and range badge style B. Hover a bar, click a bar to target it, click a column to pick that style. Party only for now; the same strip could later be reused on the raid frames. · Back to the main mockup

What the WoW API gives us, and the limits:
• UnitThreatSituation(unit) returns 0-3 (or nil) for the unit's worst threat on any mob. It can be a secret value in combat: Lua can't compare it, so the addon can't pick a colour with if/else. Plan for A, B and D: one strip texture coloured by a game colour curve (C_CurveUtil.CreateColorCurve with step points 0/1/2/3, then SetVertexColor with the result), or three stacked strips (yellow, orange, red) each shown through its alpha from a step curve, the same trick the raid "missing HP" text already uses. Our code never reads the number. Fallback if the game refuses: keep the last known colour (what the red aggro border does today). Unverified on the real client.
• UnitDetailedThreatSituation(unit, "target") returns isTanking, status, scaled %, raw %, threat value against one mob. The fill can go straight into StatusBar:SetValue and the number into FontString:SetText even when secret, but our code can't colour it by thresholds, round it, or compare members (so D's "highest" needs readable values). A game colour curve might allow threshold colours later; not planned here. Unverified on the real client.
• Healers usually target friends, so "your target" is often not a mob. A fallback to the tank's target (party1target) is possible but is still one mob only.
• Dead, ghost and not-visible members: the strip hides (B keeps an empty/striped track). Out of range: the strip is a child of the bar, so it dims with the bar (range badge B).
• Party only in this mockup; the same strip could later be reused on the raid frames.
