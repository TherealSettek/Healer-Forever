A separate "Raid" layout, with its own settings. In game this is a second layout that turns on by itself when you join a raid, and switches back when you leave (in a 5-man party or solo you keep the party layout). Switching: "Layout: Auto" picks the party layout when solo or in a party, and the raid layout in a raid. Battlegrounds count as a raid. With "Raid layout only above 5 players" (on by default) a raid of 5 or fewer keeps the party look. If the group changes during a fight, the switch waits until combat ends (secure frames can't be rebuilt in combat); the bars you have keep working until then. Try it with the "preview only" group controls in the panel. The raid layout has its own bar size, names, health text, buffs and debuffs. Nothing on this page reads or changes your party settings, and the party look stays exactly as it is now (see the reference on the right). The defaults below are only a starting point: you pick the style and the defaults.
Updating is safe. Everything you already set up for the party layout in earlier versions stays exactly as it was. The raid layout gets its own separate saved settings with their own defaults: nothing is copied from the party settings and nothing is written over them.

WoW API notes and limits for raid frames

  • Frames come from a secure group header. SecureGroupHeaderTemplate (one header per group, or one with groupBy="GROUP") creates the 40 unit buttons. Arrangement maps to header attributes: groupFilter, groupBy/groupingOrder, point, columnAnchorPoint, unitsPerColumn, maxColumns, xOffset/yOffset/columnSpacing. None of these can change in combat (size, spacing, sort, layout switch all wait for PLAYER_REGEN_ENABLED).
  • Sort by role uses groupBy="ASSIGNEDROLE", which reads UnitGroupRolesAssigned. In classic raids roles are often "NONE", and our own role detection can't feed the secure sort, so role sort may only work when roles are set. Class sort (groupBy="CLASS") always works.
  • Auras are secret in combat. Debuff icons must be drawn by the game's AuraContainer (CustomAuraContainerTemplate, filter "HARMFUL|RAID" = dispellable by me). "Icons: 1/2" fits that model. "Border only" and "Corner square" need the debuff type in our code, which may be unreadable in combat. Check on the real client before choosing them; the fallback is one icon.
  • Missing-buff markers are computed out of combat only, like the party buff buttons today. In combat they keep the last known state. The dot is too small to be its own secure button, so you buff via a click-cast binding on the bar or the smart buff key.
  • Health can be secret. The bar itself is fine (StatusBar:SetValue takes secrets). Percent text needs UnitHealthPercent and deficit text needs UnitHealthMissing (both newer API, written from memory, unverified on Forever). "Mute full-health bars" (style D) needs a colour curve from the same API; if it's missing, D falls back to normal colours.
  • Range: UnitInRange works for raid units (about 40 yd) and can be secret, so dimming uses Region:SetAlphaFromBoolean. The "OUT OF RANGE" badge from the party look doesn't fit on 22–28 px bars, so raid frames use the dim + dashed outline part of style B only. No line of sight for friendly units. Not visible: UnitIsVisible.
  • Aggro: UnitThreatSituation(unit) (can be secret; red border shown with SetAlphaFromBoolean). Incoming heals: UnitGetIncomingHeals. 40 frames × auras is the main performance cost; updates must be event-driven (UNIT_AURA with updateInfo, UNIT_HEALTH), never OnUpdate polling.
  • Preview full raid uses plain (non-secure) Frames with the same textures and FontStrings as the real buttons, filled with fake names/classes, never unit tokens, so it can't taint or cast. They have no SecureUnitButtonTemplate and EnableMouse only for the tooltip, so clicks do nothing. Placed with the raid header's saved anchor. Turned off on PLAYER_REGEN_DISABLED (combat) and on GROUP_ROSTER_UPDATE when IsInRaid() is true. Not saved in settings. Striped tag: a 16×16 diagonal-stripe .tga shipped in the addon (SetHorizTile(true)); there is no built-in Blizzard stripe texture I can vouch for.
  • Names can be secret, so "Name length" is applied as a FontString width (SetWidth + SetWordWrap(false), which cuts the text), not with string.sub. The cut point is approximate.
